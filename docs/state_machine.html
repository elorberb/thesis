Overview

Three interacting state machines drive the running product: authentication (who you are), navigation (which screen you're on), and the analysis lifecycle (turning a photo into a stored result). A fourth small machine shows how the server picks its inference backend. All states below are taken from the actual code (AuthContext, _layout.tsx AuthGuard, the screen routers, and routes/analysis.py).

entry / success screen / stable state working / async user action error

3. Analysis lifecycle

From capturing a photo to a stored, optionally-corrected result — the core value loop.

stateDiagram-v2 [*] --> Idle Idle --> Capturing: open camera / pick image Capturing --> Idle: cancel Capturing --> Uploading: submit photo state "Server: POST /api/v1/analyze" as Server { [*] --> Validating: check type + size (≤20MB) Validating --> Rejected: unsupported / too large Validating --> StoringOriginal: ok StoringOriginal --> Inferring: image_url Inferring --> Assessing: trichome + stigma results Assessing --> Rendering: maturity stage + recommendation Rendering --> StoringResult: annotated + crops StoringResult --> [*]: saved record } Uploading --> Server Server --> Success: 201 AnalyzeResponse Server --> Error: 422 / 413 / 502 / timeout Rejected --> Error Success --> Results Error --> Capturing: retry state Results { [*] --> Viewing Viewing --> Correcting: edit distribution / ratios Correcting --> Reassessing: PATCH /corrections (re-assess) Reassessing --> Viewing: updated Viewing --> Saved: save to plant } Results --> [*]: done

Client timeout is 3 minutes (TIMEOUT_MS in api/client.ts); a timeout surfaces as an error with a retry path back to the camera.
