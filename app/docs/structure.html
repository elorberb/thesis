Overview

A cannabis-flower maturity assessment product: a mobile app captures a macro photo, a FastAPI backend runs computer-vision inference (trichome detection/classification + stigma color analysis), and Supabase stores the image and results. This page maps the app/ folder — who talks to whom, and how a photo becomes a result.

mobile (Expo / React Native) api (FastAPI) backend (ML package) modal (GPU cloud) supabase (auth / storage / db)
The five parts of app/
FolderRoleKey entry point
mobile/User-facing Expo app (screens, camera, results)app/_layout.tsx, api/client.ts
api/FastAPI HTTP layer: auth, routing, storage + DB orchestrationsrc/main.py, src/routes/analysis.py
backend/Pure-Python ML package cannabis_maturity (detectors, models, assessment)src/cannabis_maturity/
modal/Optional GPU inference in the cloud (same ML package)inference.py
supabase/Postgres schema + migrations, storage bucket, authmigrations/

The ML package (cannabis_maturity) is the single source of truth — imported by both the API (local mode) and Modal (cloud mode). Inference mode is chosen at API startup via settings.inference_mode ("local" or "modal").

2. Analyze data flow (a photo → a result)

The main journey: POST /api/v1/analyze with an image file.

sequenceDiagram autonumber participant U as 📱 Mobile (camera) participant SA as 🗄️ Supabase Auth participant R as ⚙️ analysis.py participant ST as Storage service participant IS as Inference service participant ML as 🧠 cannabis_maturity participant DB as 🗄️ Postgres (analyses) U->>SA: getSession() → access token U->>R: POST /api/v1/analyze (multipart image, Bearer JWT) R->>SA: verify token (get_current_user) SA-->>R: user_id R->>R: validate content-type + size (≤20MB) R->>ST: upload_image(original) ST-->>R: image_url R->>IS: analyze(image_bytes) IS->>ML: TrichomeDetector.detect + StigmaDetector.detect (parallel) ML-->>IS: trichome_result, stigma_result IS->>ML: MaturityAssessor.assess(...) ML-->>IS: maturity_stage, recommendation IS->>ML: AnnotationRenderer.render + CropExtractor ML-->>IS: annotated_b64, crops_b64 IS-->>R: AnalysisResult (dict) R->>ST: upload_image(annotated) ST-->>R: annotated_image_url R->>DB: save_analysis(user_id, urls, result, plant_id) DB-->>R: record R-->>U: 201 AnalyzeResponse (stage, recommendation, distribution, crops)

Inference service is either LocalInferenceService (runs the ML package in-process, on threads) or ModalClient (calls the GPU function .remote()). The route code is identical for both — it just calls request.app.state.inference_service.analyze(...).
